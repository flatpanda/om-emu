Where to get the firmware

The player runs the camera's own firmware file, which this site does not hold: choose it above or drop it anywhere on this page. It is read in this browser and never uploaded.

OM System's firmware page lists the releases but offers no .BIN: its update tools fetch the file from OM System's update service. That service and its download server send no CORS headers (checked 2026-10-29), so this page cannot fetch the file for you, and it goes through no relay. In a terminal (macOS or Linux), this command asks the same service and saves the file in the current directory:


  
  
The service hands out each camera's latest release only: if OM System has published a newer one than
  the release this player runs, the player refuses it and names the file it needs. The download is subject to OM
  Digital Solutions' software licence, which the service's reply carries. With the repository cloned,
  node emu/bin/fetch-fw.mjs does the same and also unpacks the blocks for the node tools.

  Scene and image sensor (S-SCENE stand-in)
  
The camera's sensor, image pipeline, AF and release are not modelled. This stand-in renders a synthetic scene
  (layers at three distances, a thin lens on a Four Thirds sensor, the exposure triangle) into the live-view bank, and the
  firmware's own through-image API shows it on the IMG1 plane (it needs A15). S1 focuses on the layer under the AF point
  S2 records a capture with the exposure in use and REC starts and ends a clip: all three are the stand-in's, not the firmware's.
  The firmware's camera application answers S1 and S2 itself (the date prompt, the shooting information, the focus
  confirmation, the capture display for the shutter time in use, the rec view), with the modules' notifications of a release
  stood in (S-RELSEQ). REC records at mode-dial position 7 after the LLPSW firmware key (Firmware keys, 1.1.4 0x121c) is
  released; with LLPSW pressed, as the lab's idle image has it, the application refuses the key's function.
